# BrandLab

**Dynamic app branding on real devices: launcher icons, app names and home screen widgets that change with user activity.**

BrandLab is an educational Expo app. It shows how apps like streak-based learning apps change their icon, name and widgets depending on how active a user is. Everything uses the real platform APIs: activity aliases and Jetpack Glance on Android, alternate icons and WidgetKit on iOS. Failed native calls are shown as failures, never as fake successes.

All icons and artwork are original.

---

## Features

| Feature | Android | iOS |
| --- | --- | --- |
| Switch launcher icon (5 variants) | ✅ Activity aliases | ✅ Alternate icons |
| Switch app display name (4 presets) | ✅ Activity aliases | ❌ Not possible at runtime: explained in app |
| Home screen widget (small and medium) | ✅ Jetpack Glance | ✅ WidgetKit (iOS 17+) |
| Widget light/dark mode | ✅ Follows system | ✅ Follows system |
| Tap widget to open app | ✅ | ✅ |
| Engagement simulator → branding state | ✅ | ✅ |
| In-app light/dark theme | ✅ | ✅ |

**Branding variants:** Default, Happy, Sleepy, Sad and Celebration.

| Simulated activity | Resulting look |
| --- | --- |
| Active today | Happy |
| Missed 1 day | Sleepy |
| Missed 3 or 7 days | Sad |
| Daily goal complete | Celebration |

## Requirements

- **Node.js** 22.13+ and **Yarn** 1
- **Android:** Java 17, Android SDK / Android Studio, a device or emulator
- **iOS:** macOS, Xcode 26.4+, CocoaPods 1.16.2+, an Apple Developer team (needed for App Groups and signing)

Pinned stack: Expo SDK 58, React Native 0.88, React 19.3, TypeScript 5.9.

> ⚠️ **Expo Go is not supported.** BrandLab uses a custom native module and a widget extension, so it needs a development build.

## Getting started

```sh
yarn install
npx expo prebuild            # generates android/ and ios/ (not committed)
```

### Android

```sh
yarn android                          # build, install and launch
npx expo run:android --device         # choose a connected device
```

### iOS

1. Add your Apple team ID to `app.config.ts`:
   ```ts
   ios: { appleTeamId: 'XXXXXXXXXX', ... }
   ```
2. Make sure the App Group `group.com.brandlab.demo` is available to your team. Use your own group ID if needed; see [sync points](docs/PROJECT_CONTEXT.md#11-values-that-must-stay-in-sync).
3. Run:
   ```sh
   yarn ios
   ```

### EAS Build

```sh
npx eas-cli build --platform android --profile development
npx eas-cli build --platform ios --profile development
```

Profiles are in `eas.json` (`development`, `preview`, `production`).

## Using the app

| Tab | What it does |
| --- | --- |
| **Home** | Current launcher icon, app name, progress and streak, plus shortcuts |
| **Icons** | Apply any of the 5 icon variants to the launcher |
| **Widgets** | Preview the widget and request a refresh. Shows how to add the widget. |
| **Activity** | Run engagement scenarios. Updates the state, icon and widget together. |
| **More** | Appearance (System/Light/Dark), platform capability report |

**App display name** opens from Home or More.

**Add the widget:** touch and hold the home screen → Widgets (Android) or **+** (iOS) → BrandLab → pick a size.

## Project structure

```
app/                       Screens (Expo Router tabs)
src/services/              Business logic: engagement rules, storage, native calls
src/state/                 BrandingContext (app-wide state + actions)
modules/dynamic-branding/  Local Expo Module (Kotlin + Swift) and Android Glance widget
targets/widget/            iOS WidgetKit extension
plugins/                   Config plugin that generates aliases, resources and icon sets
assets/icons/              Original icon artwork
docs/PROJECT_CONTEXT.md    Full architecture and implementation reference
```

`android/` and `ios/` are **not in git**. They are generated by `npx expo prebuild` from `app.config.ts`, `plugins/`, `modules/` and `targets/` (Expo's [Continuous Native Generation](https://docs.expo.dev/workflow/continuous-native-generation/)). Run prebuild after cloning or after changing native config. Never put lasting changes directly in `android/` or `ios/`; `npx expo prebuild --clean` deletes and recreates them.

## Platform notes

- **Android:** icons and names can only be chosen from the values declared at build time. Some launchers, including Samsung One UI, **close the app** when its icon or name changes. This is expected; reopen it from the home screen.
- **iOS:** iOS shows a system alert when the icon changes. The display name can only be changed by rebuilding.
- **Widgets:** refreshes are requests. The OS decides when to redraw.

Details: [Platform limitations](docs/PROJECT_CONTEXT.md#12-platform-limitations).
